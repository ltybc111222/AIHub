# План проекта (краткий)

Версия от 13.11.2026. Документ задаёт рамку. Архитектура и нарезка задач появятся в отдельном документе после разведки и прототипа.

## Цель

Дать человеку один удобный интерфейс к нескольким ИИ-ассистентам, в которых у него уже есть аккаунты, без посредников между ним и сервисом.

## Для кого

Сначала автор и его друзья, затем студенты и любые пользователи через Chrome Web Store и Firefox Add-ons.

## Режимы работы

### Режим 1, основной: «Эстафета»

Один диалог в интерфейсе расширения, который по очереди ведут разные ассистенты. Пользователь работает над длинной задачей в одном месте и не переключает вкладки. Когда у одного сервиса закончился лимит или пользователь сам захотел сменить ассистента, диалог продолжается в следующем.

Что входит:

1. Единое поле ввода и единая лента диалога в расширении.
2. Отправка запроса в один выбранный сервис и чтение его ответа в ленту.
3. История диалогов, которая хранится только локально в браузере.
4. Передача контекста при смене ассистента: новый сервис получает постановку задачи и последние реплики. Пользователь видит и может поправить этот текст до отправки.
5. Индикация по каждому сервису: какая модель выбрана, идёт ли генерация, есть ли ошибка (нужен вход, капча, исчерпан лимит).
6. Подсказка сменить ассистента, когда сервис сообщил об исчерпании лимита. Переключение выполняет пользователь.

Расширение не обходит ограничения сервисов. У каждого сервиса используется собственный аккаунт пользователя в пределах того, что этот сервис ему даёт.

### Режим 2, продвинутый: «Сравнение»

Один запрос уходит сразу в несколько сервисов, ответы показываются рядом. Делается после режима 1 на том же каркасе адаптеров.

### Позже

1. Список доступных моделей и сведения о лимитах с пометкой достоверности (точно, по сообщению сервиса, оценка).
2. Ручная калибровка: пользователь сам указывает поле ввода, если автоматический поиск не справился.
3. Экспорт и импорт истории файлом.

## Чего не делаем

- Свой сервер, аккаунты, синхронизация между устройствами.
- Телеметрия и любая аналитика.
- Внутренние API сервисов, работа с куками и токенами.
- Встраивание сервисов в iframe со снятием их защитных заголовков.
- Удалённо обновляемые селекторы или конфигурация.
- Официальные API по ключу пользователя. Вернёмся к этому только при явной необходимости.
- Монетизация в любом виде.

## Ключевая техническая задача

Задач три.

**Поиск элементов.** Находить поле ввода, кнопку отправки, переключатель модели и текст ответа так, чтобы смена вёрстки сервиса не ломала расширение. Подход: несколько независимых сигналов с оценкой кандидатов.

1. Семантика: роли, ARIA-атрибуты, ландмарки страницы.
2. Структура и геометрия: типизация областей страницы (история, диалог, поле ввода) и поиск внутри области.
3. Поведение: узел, в котором после отправки растёт текст, считается ответом.
4. Ручная калибровка как последний рубеж.

Каждый сервис описывается адаптером и конечным автоматом состояний с проверкой результата после каждого шага.

**Чтение ответа.** В режиме 1 оно обязательно с первой версии: без него нет ни единой ленты, ни истории. Ответ нужно забирать с разметкой (код, списки, таблицы, формулы) и надёжно определять конец генерации.

**Передача контекста.** У расширения нет своей модели, поэтому сжать диалог оно не может. Пакет передачи собирается механически: закреплённая пользователем постановка задачи и последние реплики в пределах лимита длины сообщения нового сервиса. Пакет всегда показывается пользователю перед отправкой.

**Где живут страницы сервисов.** Пользователь не переключает вкладки, значит страница сервиса работает в фоне. Встраивание в iframe исключено. Фоновые вкладки браузер замедляет, и это может ломать потоковый вывод ответа. Вариант размещения выбирается по результатам прототипа.

## Модель угроз (черновик)

| Угроза | Мера |
| --- | --- |
| Расширение или его обновление отправляет данные наружу | Нет бэкенда, `connect-src 'none'` на страницах расширения, запрет сетевых вызовов проверяется в CI, воспроизводимая сборка |
| Вредоносный текст в ответе ассистента исполняется в интерфейсе расширения | Ответ считается недоверенными данными: только текстовая вставка или санитайзер, строгий CSP |
| Компрометация зависимости | Минимум зависимостей, фиксированные версии, проверка в CI |
| Избыточные права | Доступ только к доменам сервисов, выдаётся пользователем по одному сервису |
| Локальная история диалогов доступна другим людям за тем же компьютером | Хранение только в `storage.local` без синхронизации, кнопка полной очистки, опциональное шифрование паролем |
| Текст из одного сервиса попадает в другой без ведома пользователя | Пакет передачи контекста показывается и подтверждается перед отправкой |
| Личные данные в публичном репозитории | Очистка материалов разведки, правила в CONTRIBUTING.md |

## Риски вне кода

- **Условия сервисов.** Режим 1 требует автоматического чтения ответов, а оно прямо запрещено условиями всех трёх сервисов (см. [отчёт разведки](01-recon-desk.md)). Риск блокировки аккаунта несёт пользователь, и расширение обязано честно предупреждать об этом при включении каждого сервиса. Смягчающие меры: одно действие пользователя равно одной отправке, никаких фоновых запросов, отказ от внутренних API.
- **Позиционирование.** Формулировка «тратить бесплатные лимиты нескольких сервисов» в описании магазина может быть воспринята как обход ограничений. В публичных текстах описываем функцию как единое рабочее место для своих аккаунтов.
- **Ревью магазинов.** Доступ к нескольким сайтам вызывает углублённую проверку. Нужны политика приватности и точное описание единственного назначения.
- **Хрупкость.** Сервисы меняют интерфейс без предупреждения, а обновление через магазин занимает дни.

## Критерии успеха первой версии

1. Запрос доходит до сервиса, а ответ целиком попадает в ленту в 95% попыток на актуальных версиях интерфейсов.
2. Диалог можно продолжить в другом ассистенте в два действия: выбрать сервис и подтвердить пакет контекста.
3. При сбое пользователь видит понятную причину, а не молчание.
4. Проверка манифеста и кода подтверждает каждый принцип из README.
5. Сборка из исходников побайтно совпадает с опубликованной.
