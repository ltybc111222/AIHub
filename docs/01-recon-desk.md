# Разведка, часть 1: кабинетная

Дата: 13.11.2026. Источники перечислены в конце. Это сводка фактов для планирования, а не юридическое заключение.

Часть 2 (живая структура интерфейсов трёх сервисов) снимается отдельно в залогиненном браузере.

## 1. Условия сервисов

| Сервис | Документ | Что запрещено (дословно, фрагменты) | Исключения | Возраст |
| --- | --- | --- | --- | --- |
| ChatGPT | Terms of Use, п. 2(c)(iv), дата в тексте не указана | «except as permitted through the API, use any automated or programmatic method to extract data or output from the Services» | Только API | 13+, до 18 с согласия родителей |
| Claude | Consumer Terms, разд. 3, п. 7 и п. 4, действует с 08.10.2025 | «to access the Services through automated or non-human means, whether through a bot, script, or otherwise»; «To crawl, scrape, or otherwise harvest data» | API-ключ или явное разрешение Anthropic | 18+ |
| DeepSeek | Terms of Use, п. 3.5(3), ред. 27.03.2026 | «using any robots, spiders, or other automatic setups»; «capturing, copying any content of the Services» | Нет, только «без разрешения» | Для взрослых, до 18 с согласия опекуна |

### Что из этого следует

1. **Формулировки разные по охвату.** У OpenAI запрет касается автоматического *извлечения* данных и ответов. У Anthropic запрещён сам *доступ* через скрипт, то есть под текст попадает уже автоматический ввод, а не только чтение. У DeepSeek запрещены «автоматические установки» и копирование контента.
2. **Разделение на «ввод» и «чтение» подтверждается.** Автоматическое чтение ответов прямо названо у всех трёх. Ввод прямо назван только у Anthropic.
3. **Claude несёт наибольший риск.** Кроме самой формулировки, в феврале 2026 Anthropic публично подтвердила запрет сторонних инструментов, работающих через подписку (речь шла об OAuth-токенах, расширения браузера в сообщении не упоминались). Это показывает, что условие применяется на практике.
4. Ни один документ не содержит исключения для расширений браузера или вспомогательных инструментов.

Версию условий OpenAI для стран вне США (ROW) получить не удалось, проверена основная версия.

## 2. Требования магазинов

### Chrome Web Store

- **Единственное назначение:** «An extension must have a single purpose that is narrow and easy to understand.»
- **Минимальные права:** запрашивать самые узкие права, иначе возможен отказ.
- **Удалённый код запрещён.** Удалённая конфигурация без логики формально разрешена, но мы ей не пользуемся по собственным принципам.
- **Обфускация запрещена,** минификация допустима.
- **Сообщения от имени пользователя:** запрещены расширения, которые отправляют сообщения «without giving the user the ability to confirm the content and intended recipients». Наше правило «одно действие пользователя равно одной отправке» с явным выбором сервисов этому соответствует, и это надо сохранить в интерфейсе.
- **Политика приватности** обязательна, если расширение обрабатывает пользовательские данные. Текст страниц чатов расширение обрабатывает локально, поэтому политику публикуем в любом случае.
- **Чужие бренды:** нельзя создавать впечатление, что продукт одобрен или выпущен другой компанией. Названия и логотипы сервисов в названии и иконке расширения не используем.
- **Вкладка Privacy:** обоснование каждого права, отметка «без удалённого кода», подтверждение раскрытия данных. Расхождение с реальным поведением ведёт к удалению.
- Нужна двухфакторная защита аккаунта разработчика и разовый регистрационный взнос (сумма на странице не указана, уточнить при регистрации).

### Firefox Add-ons

- **Обязательный ключ манифеста** `browser_specific_settings.gecko.data_collection_permissions`. Для расширения без сбора данных значение `"required": ["none"]`. Для новых расширений обязательно с 03.11.2025, без ключа подпись не выдаётся.
- **Минимальные версии:** Firefox 140 для настольных систем, 142 для Android.
- **Исходный код** подаётся, если используется сборщик или минификатор. Ревьюер пересобирает и сравнивает: различий быть не должно. Нужны lock-файл и точная инструкция сборки. Среда ревьюера по умолчанию: Ubuntu 24.04, ARM64, Node 24, npm 11.
- **Удалённый код запрещён,** передача данных только в объёме, необходимом для функций.
- С 01.12.2026 вступают в силу обновлённые политики, их текст ещё не изучен.

### Вывод

Наши принципы закрывают почти все требования обоих магазинов. Требование Firefox о побайтно воспроизводимой сборке совпадает с нашим седьмым принципом, поэтому среду сборки стоит сразу выровнять под среду ревьюера.

## 3. Расширение-аналог: MultAI

Открытый проект (MIT, версия 0.1.0, около 30 коммитов). Изучены манифест, правила сети и адаптеры ChatGPT, Claude, DeepSeek.

### Архитектура, которую мы не повторяем

- Сайты сервисов встроены в iframe на странице расширения.
- Для этого правило `declarativeNetRequest` удаляет у ответов сервисов девять защитных заголовков, включая `Content-Security-Policy`, `X-Frame-Options` и `Cross-Origin-Opener-Policy`, причём и для основной вкладки.
- Дополнительно в страницу сервиса внедряется скрипт против защиты от встраивания.
- Ответ читается нажатием кнопки «Копировать» с перехватом буфера обмена.

Это ослабляет защиту самих сервисов в браузере пользователя и вмешивается в буфер обмена. Решение не делать iframe подтверждается.

### Якоря, которые использует аналог

Не проверены на живых сайтах, нужны как гипотезы для части 2.

| Элемент | ChatGPT | Claude | DeepSeek |
| --- | --- | --- | --- |
| Поле ввода | `#prompt-textarea`, `contenteditable` с классом `ProseMirror` | `div[contenteditable="true"].ProseMirror` | `textarea#chat-input` |
| Отправка | `button[data-testid="send-button"]`, `aria-label*="Send"` | `button[aria-label="Send message"]` | `div[role="button"][aria-label*="Send"]` |
| Идёт генерация | `button[data-testid="stop-button"]` | `button[aria-label*="Stop"]` | `button[aria-label*="Stop"]` |
| Ответ | `div[data-message-author-role="assistant"]` | `div.font-claude-message` | `div.ds-markdown` |

### Наблюдения

1. **Ввод действительно самое хрупкое место.** Для полей `contenteditable` аналог перебирает семь способов вставки подряд (`beforeinput`, `execCommand`, имитация вставки из буфера, события композиции, посимвольный ввод, прямая запись текста) и после каждого проверяет, появился ли текст.
2. **DeepSeek самый простой:** обычный `textarea`, достаточно нативного сеттера значения и события `input`. Выбор DeepSeek для прототипа подтверждается.
3. **Семантические якоря существуют, но неравномерно.** У ChatGPT есть устойчивые `data-testid` и `data-message-author-role`. У Claude ответ находится только по имени CSS-класса, это слабое место.
4. **Якоря по `aria-label` привязаны к английскому интерфейсу.** Для русскоязычных пользователей они не сработают. Нужны признаки, не зависящие от языка: роль, положение, поведение.
5. **Конец генерации** определяется только исчезновением кнопки «Стоп». Одного признака мало, нужен второй (стабильность текста).

## 4. Что не удалось получить

- Историю правок селекторов у аналогов, то есть частоту поломок по каждому сервису.
- Исходный код второго аналога (AI Chat Broadcaster): ссылки на репозиторий в магазине нет.
- Версию условий OpenAI для стран вне США.
- Сумму регистрационного взноса Chrome Web Store.

## 5. Влияние на план

1. Объём первой версии (ввод без чтения) выбран верно и снижает риск по условиям ChatGPT и DeepSeek.
2. По Claude нужно отдельное решение: автоматический ввод прямо подпадает под формулировку условий.
3. Признаки элементов не должны опираться на текст интерфейса.
4. Среда сборки: Node 24, lock-файл, инструкция сборки в README с первого коммита кода.
5. В интерфейсе пользователь всегда видит текст и список сервисов до отправки.
