# Как устроена работа

## Задачи

Каждая задача оформляется как issue с критериями приёмки. Работа без issue не начинается.

## Ветки и PR

- `main` всегда в рабочем состоянии, прямые коммиты в него запрещены.
- Ветка создаётся под одну задачу и живёт недолго: `<поток>/<номер-issue>-<кратко>`, например `b1/12-composer-locator`.
- Изменения попадают в `main` только через PR с пройденным CI.
- Один PR решает одну задачу. Попутные правки выносятся в отдельный PR.

## Что не принимается

- Телеметрия, аналитика, сбор ошибок, любые сетевые вызовы, не описанные в архитектурном плане.
- Удалённо загружаемый код или конфигурация.
- Обращения к внутренним API сервисов, работа с куками и сессионными токенами.
- Расширение прав в манифесте без отдельного обсуждения в issue.
- Новые зависимости без обоснования в PR.

## Данные в репозитории

Репозиторий публичный, история коммитов остаётся навсегда. Не коммитьте ключи, куки, личную переписку с ассистентами и снимки страниц с персональными данными. Материалы разведки очищаются перед коммитом.
